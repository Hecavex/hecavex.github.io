# Evidence and visual acceptance

Automated dimensions and payload checks are release controls, not artistic approval. Keep the current palette and distinguish a cover from a claim-bearing figure.

Before replacing an image series, review a primary investigation, technical guide, historical screenshot-led article and text-led Signal Brief in both languages.

Run `node scripts/editorial-previews.mjs <private-output.html>` after content changes. The output must stay outside this repository. It places each cover, 320 CSS-pixel card and 600 CSS-pixel social image together without treating generation as owner approval.

Check the actual crop, title legibility, contrast and EN/LT meaning. Diagrams must state their abstraction and must not imply an unsupported relationship. A picture that resembles a dashboard is not telemetry. A generated illustration is not a screenshot.

For evidence figures, retain the source capture, identify the visible claim and explain collection or reconstruction limits. Hashes of images identify images, not original malware, network responses or their collection times. Never resize or recolour the only retained original.

For click-through work, preserve a dated Search Console export with query, page, device, country and language context. Compare equivalent windows and note publication, indexing and ranking changes. Do not attribute a CTR change to an image or headline without considering those factors. Authenticated external preview and editorial approval remain human steps.
